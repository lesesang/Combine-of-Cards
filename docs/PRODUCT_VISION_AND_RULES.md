# 제품 목표 및 확정 공통 규칙 — 컴바인 오브 카드즈

> **Codex용 최신 규칙·우선순위 색인:** [CODEX_RULES_REFERENCE.md](CODEX_RULES_REFERENCE.md) · [CODEX_HANDOFF.md](CODEX_HANDOFF.md) · [CODEX_IMPLEMENTATION_PLAN.md](CODEX_IMPLEMENTATION_PLAN.md). 카드 COC-21-002 마검의 ATTACK 페이즈 HP30 지불과 다음 자기 턴 ×2 곱셈 중복은 PR #58 최신 사용자 확정이며, 오래된 턴 시작 구현은 폐기됨.

**기준:** 2026-10-13 인계 / 공식 규칙·카드 텍스트 v1.3. 이 문서는 *코드에 모두 구현되었다는 뜻이 아니다*. 카드별 특례가 일반 규칙보다 우선하며, 실제 카드 원문 정본이 저장소에 추가되면 그 문구와 반드시 대조한다.

## A. 개발 목적과 성공 모습

동호회에서 만든 오리지널 TCG **《컴바인 오브 카드즈》를 실제로 대전 가능한 웹 서비스**로 구현한다.

1. **카드 원문의 의미를 보존한 완전 자동 판정**: 발동 가능 여부, 코스트 지불, 상대 대응, 주사위, 효과 처리, 지속·종료, 카드 이동, 패배·무승부를 서버가 재현한다. 복잡한 일체화·퓨전·라피드·얼라이즈·장착·복사·부활·조종권 변경도 예외 없이 처리한다.
2. **사전 구성 덱 기반 대전**: 덱 24개 중 하나를 고른다. 덱 간 메인/엑스트라 카드 혼합 불가. 게임 중 카드 탈취나 복사 등 합법적인 효과는 가능하다.
3. **실제 사람과 온라인 대전**: 방 생성·참가, 재접속, 룸별 사용자 구분, 동시 입력·대응 단계, 확인 가능한 재판정 로그와 비공개 손패.
4. **혼자 AI 대전**: 자기 덱 선택, AI 상대 덱 지정 또는 랜덤, 난이도 하/중/상. AI도 사람과 동일한 카드/효과 검증을 사용하며 반칙이나 비공개 상대 손패 활용이 없어야 한다.
5. **룰·카드 버전 고정/감사**: 대전 시작 시 규칙과 카드 버전을 고정하고 사건·발동·해결 순서를 기록한다. 카드 효과를 구현하는 과정에서 충돌/애매함을 찾아 *의도를 보존한 개선안*을 제안한다.
6. **서비스 경험**: 읽기 쉬운 카드 도감, 검색·효과 텍스트·조건 및 자동화 상태, 명확한 대상 선택, 대전 보드/로그, 모바일 대응, 관리자용 테스트 대전(향후 구현), 운영/보안.

### 성공 기준

대전 중 일반 사용자가 별도로 판정을 계산하거나 상대의 수동 승인에 의존하지 않아도 **유효한 덱 24종의 모든 카드 효과가 룰북대로 작동**해야 한다. 테스트가 통과하는 것만으로 충분하지 않으며 254개 카드 *각 효과별*로 정답 사례와 불법 사례가 증명되어야 한다. 베타의 현재 수동 판정 및 AI 효과 건너뛰기는 임시 구조이다.

## B. 대상 카드 데이터

- 원본 수집: 과거 제출된 **32개 MHTML 덱 자료**(15개 + 17개).
- 삭제 확정 8개: **합체 기계 / 코미컬 / 럭키 / 카지노이드 / 비트스타즈 / 파트너 몬스터즈 / 코브라 / 아홉꼬리**.
- 최종 **24개 덱, 254개 카드 항목**: 메인 215 + 엑스트라 21 + 생성·진화 18. 이전 자료의 27개/25개 덱 표기는 사용하지 않는다.
- 유효 덱: G-덱, 영매, 카툰, 연금술, 포식자, 츠쿠모가미, 생명의 대장장이, 언데드, 용·드래곤, F=HERO, 괴도, 스톰, 파라오, 토우병사, 버닝데몬즈, 저주·악마, 블랙 메탈, 라이드 위저드, 지니어스 세컨드, 지니어스, 슈페리얼, 자연속성, 마술사, 원소 마술사.
- 카드 식별자는 COC-XX-YYY 형태. 다른 덱에 동명이인 카드가 있어도 ID로 구분.
- 기초 카드 종류: **주문 / 몬스터 / 일체화**. 일체화는 플레이어 자신이 몬스터가 된 상태이며 필드 몬스터 3칸을 쓰지 않는다.
- 엑스트라 분류: **퓨전 / 라피드 / 얼라이즈**. 같은 카드의 소재와 특수 소환 조건은 개별 명세가 우선한다.
- 조건, 효과, 카드 특례를 문서화할 때 가급적 **소환/발동 조건 → 비용 → 대상/선택권 → 처리 순서 → 지속/종료 조건 → 실패 처리**로 통일한다. 숫자와 효과 의미는 절대 변경하지 않는다.

### 덱·드로우·리로드

1. 게임 시작 또는 명시적 섞기 시 서버가 덱 순서를 무작위 확정하고, **덱 맨 위부터** 드로우한다.
2. **빈 덱에서 드로우를 시도할 때** 리로드. 묘지에 카드가 있으면 묘지 전체를 덱으로 되돌려 섞고 드로우를 이어 간다.
3. 리로드 횟수 제한 없음. 같은 플레이어의 첫 리로드 피해 **100**, 이후 **150, 200, …**, 리로드마다 +50.
4. 덱과 묘지 모두 비었더라도 드로우는 실패하고 리로드 피해는 적용된다. 드로우가 실패한 행동과 추후 다음 드로우 시도를 구분한다.
5. 단지 덱을 0장으로 만들거나, 덱에서 묘지로 카드가 이동했다는 이유만으로 자동 리로드하지 않는다. *드로우 시도*가 조건이다.
6. 여러 장 드로우는 카드 한 장씩 시도하며 중간 리로드·패배와 카드별 드로우 실패 반응을 처리한다.
7. 덱 반환은 **반환 카드만** 기존 덱의 인덱스 0부터 맨 아래까지 **무작위 위치**에 끼워 넣는다. 기존 덱은 그 사건만으로 다시 섞지 않는다. 별도 명시된 셔플 효과는 따로 처리한다.

### 2026-10-13 추가 확정 사항

- 남은 공격 기회는 **공격 금지·동결·공격력 0에서도 효과 비용으로 지불 가능**. 공격 선언 시 공격 기회 소모, 상대 대응으로 대상 소실 시 합법 대상 재선택은 추가 비용 없음.
- 소환 대응은 **소환 선언 → 합법성 검사 → 소재·비용 지불 → 양측 대응 → 해결**이고 무효화해도 지불한 비용은 돌려주지 않음. 엑스트라21종은 스톰블레이거 무효화 대응을 구현했다. 일반/효과/토큰 소환 등 범용 연결은 미완료.
- 황금/파프니르·토큰 사건 및 그 밖의 **확정된 17개 재정**은 [RULINGS_CONFIRMED_2026-10-13.md](RULINGS_CONFIRMED_2026-10-13.md) 참조.

### 영역 이동·소유·일체화

- 원래 소유자와 현재 조종자를 구분한다. 상대 몬스터를 탈취해도 패/덱/묘지/제외로 이동할 때는 기본적으로 **원래 소유자의 영역**으로 간다. 카드별 특수 반환 조건은 예외.
- 기본적으로 파괴/버리기/릴리스는 묘지 이동. 제외/게임에서 제거는 제외 영역(개별 카드의 표현 오탈자 정정 반영). 토큰은 필드를 벗어나면 소멸.
- 얼라이즈에 겹친 소재는 **파괴뿐 아니라 패/덱/묘지/기타 영역으로 이동할 때도 함께 이동**한다. 추후 서버에서 일괄 트랜잭션으로 보장해야 한다.
- 필드에서 몬스터 취급을 받은 주문은 실제로 그 상태를 얻는 **단발 처리**이며 이후 효과 무효화만으로 자동 롤백하지 않는다. 일반 주문은 사용 후 묘지로 간다. 주문이 만들어 낸 독립 지속 효과는 카드가 묘지에 있어도 별도 상태로 유지한다.
- 일체화/조종 변경/장착·능력치 효과는 분리된 상태로 추적한다. 일체화 강제 해제 시 해당 카드 묘지 이동 및 연결 장착 카드 함께 처리 등 확정된 예외를 따른다.
- 게임 내 능력치는 기본/현재/취급 공격력과 일시/영구 변경을 별도 기록해야 한다. 특정 카드의 수치가 동적으로 결정되는 경우 기본 0으로 가정하여 영구 고정하면 안 된다.

## D. 엔진 설계 확정 사항 (이전 개선안 6개 승인)

1. **발동 소스 유효성**: 일반적인 필드 발동 효과는 해결 전에 발동 카드가 필드를 떠나면 무효화. **파괴 시 발동, 묘지 발동, 자신을 비용으로 묘지로 보낸 경우, 이미 독립 등록된 지속 효과, 개별 확정 예외(깐깐한 감독관)**는 해당 소스 이동 후에도 해결.
2. **독립 지속 상태**: 주문의 물리적 위치와 독립된 지속 효과 인스턴스, 카운터, 종료 사건 유지. 라인의 황금이 대표 사례.
3. **자동 트리거 선언 순서**: 명시된 특수 우선도 예외가 먼저. 동일 우선도에서는 현재 턴 플레이어가 자신 효과의 선언 순서를 먼저 선택하고, 상대가 자신의 순서를 선언한다. 실제 체인 해결은 **나중에 선언된 것부터**. 사용자 선택이 필요한 경우 서버가 임의 순서를 확정해서는 안 된다.
4. **복사 기록 분리**: 원본·효과 실행자·복사 시점 상태 및 이벤트 이력·사용 횟수와 그 이후 기록을 독립 관리한다. 조건, 사건, 비용, 처리 분리. '원죄를 저지른 자'는 조건(그 안에 포함된 비용 포함) 무시 가능하지만, 사용 금지나 처리 중 별도 비용을 임의 생략하지 못한다.
5. **공격력 값 분리**: 인쇄/기본·현재·취급 수치, 일시/영구 변경, 동적으로 정해진 수치를 별도 표현. 블랙 메탈 매지션 실제 공격 50 / 조건 판정용 취급 공격 250.
6. **무한 반복 안전성**: 합법적 반복을 임의로 약화시키지 않는다. 완전히 동일한 상태가 무한 반복되는 경우 상태·이력 기반으로 탐지하고 로그를 남긴 뒤 안전하게 중지한다. 단순 고정 70행동/256스택 제한은 현재 베타 서버 보호일 뿐 이 확정 원칙을 완전히 구현한 것은 아니다.

### 처리 실패·대상·효과 원칙

- 비용을 치를 수 없으면 발동 거부. 그 후 해결 중 대상 소실 시 룰에 따라 유효 대상 재선택, 없으면 효과 실패 처리.
- 명시된 필수 여러 단계는 가능한 만큼 수행할 수 있으나, 발동 전 필수 비용 불충족과 해결 도중 일부 처리가 불가능한 상황을 구분한다.
- 소환 조건 무시가 **사용 금지**까지 무시할 수 있는 것은 아니다.
- 동일 사건의 여러 피해/파괴/승패를 중간 순서에 좌우되지 않도록 스냅샷/동시 사건과 응답 스택으로 처리한다.
- 단순히 효과의 원문 문장 순서를 정리한다고 규칙을 새로 확정한 것은 아니다.

## E. 기술·데이터 원칙

- 게임 규칙 판정/다이스/무작위/코스트/비공개 카드 선택/승패는 **서버 권위**. UI/AI가 서로 다른 규칙을 실행하지 않는다.
- 엔진은 게임방 상태를 직렬화할 수 있어야 하며 결정적인 재현·감사/로그를 지원한다.
- UI는 카드를 사용하기 전에 발동 조건, 비용, 선택권/대상, 실제 자동화 범위를 표시해야 한다.
- 서버는 무효 액션을 거절하고 부분 실행 상태가 남지 않도록 **원자적 트랜잭션**으로 처리한다.
- 공식 정본 카드 데이터는 변경 이력/원문 증거를 남기고 게임이 시작되면 고정된 버전을 적용한다.
- 정식 목표에 필요한 운영 보안은 ROADMAP_AND_ACCEPTANCE와 ARCHITECTURE_AND_RUNBOOK 참조.
