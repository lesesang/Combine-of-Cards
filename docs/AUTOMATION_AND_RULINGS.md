# 컴바인 오브 카드즈: AI 및 카드 판정 베타 검증 보고서

작성 기준: 공식 규칙 v1.3, 유효 덱 24개, 카드 항목 254개. 판정 문제를 조용히 자동 보정하지 않는다.

## 검증 보강 (2026-10-12)

- **24개 덱**을 모두 AI 상 난이도 상대 덱으로 차례로 선택해 API 기반 연속 턴 스모크 테스트를 수행했다. 최근 로컬 재검사에서 대전 API 오류 및 AI 판정 중단 0건. 대전이 끝날 때까지의 모든 카드 효과를 검증한 것은 아니다.
- 파라오 덱에서 미라 병사 등 **생성 토큰이 공격 시** 카드 도감 조회 실패로 AI가 중단되던 버그를 수정했다. 생성 유닛은 자체 토큰 데이터를 참조한다.
- 주문 대상은 아군/상대 플레이어 및 필드 몬스터에서 명시적으로 선택 가능하다. 유효하지 않은 대상은 임의 대상으로 바꾸지 않고 거부한다.
- 기본 다이스 상한은 룰북의 **1억**으로 수정했고, 몬스터가 필드에서 패·덱·묘지 등으로 돌아갈 때 단발 강화와 상태를 초기화한다.
- 두 몬스터 선택 효과에서 **서로 다른 유효 대상 2장**을 검증한다. 다수 카드 사용 횟수는 현재 사용한 카드도 포함하도록 보정했다.
- 버닝 데몬즈 버스트의 양측 피해는 동일한 주사위를 적용한 다음 한 번에 승패 판정한다.
- 카드 254종 전체 자동 판정은 아직 구현되지 않았다. 등록된 **주문 핸들러 55개/주문 109종**은 일부 기능에 국한되며 몬스터 지속/유발 효과, 비정상적인 연계 및 전 카드 소재 판정은 아직 전수 검증되지 않았다.
- 로컬 검증: `npm run check:data`, `npm test` (17건), `npm run test:matrix` (24개 덱별 AI 연속 진행).

## 지금 구현된 범위

- 서버가 턴, 일반 드로우, 리로드(누적 피해), 소환, 기본 공격 다이스, 승패와 상대 대응을 처리한다.
- `POST /api/ai`에서 `deckId`, `aiDeckId`(또는 `random`), `difficulty`(`easy`, `medium`, `hard`)를 받아 혼자 대전할 수 있다. 게임 결과와 AI 행동은 서버에서 결정되며 상대 손패는 클라이언트에 전송하지 않는다.
- '하'는 합법적으로 고른 선택지 중 무작위로 사용하고 일부 사용 기회를 포기한다. '중'은 공격력·효과 기준의 휴리스틱으로 선택한다. '상'은 높은 공격력을 우선하고 제거 가능한 위협을 탐색한다. **세 난이도 모두 학습된 강화학습 모델이 아니라 규칙 기반 AI**다.
- `src/automated-effects.mjs`에는 정확한 카드 ID를 기준으로 동작하는 확정 효과 핸들러들이 있다. 구현 범위는 런타임 API 응답의 `automation.supportedSpells`로 확인할 수 있다.
- 효과 지원이 없는 주문은 AI 모드에서 사용할 수 없으며 패에서 소모되지 않는다. 상대 확인 기반의 수동 판정은 2인 대전에서만 사용한다.
- `npm test`는 인증, 손패 비공개, AI 세 난이도, 자동 턴 진행, 권한 검사를 검증한다. 테스트 통과는 254개 모든 카드 효과의 정확성을 보장하지 않는다.

## 알려진 구현상의 제한 (오류 은폐 금지)

1. 자동 처리되지 않는 카드 효과를 **작동하는 것으로 설명해서는 안 된다.** 지원 목록은 카드 단위이고, 일부 핸들러는 해당 카드의 한 효과만 구현한 경우가 있으므로 정식으로는 **부분 지원**이다.
2. 현재 일체화·몬스터의 일부 자동 발동은 직접 구현한 카드 ID에만 적용된다. 소환 제한 전수 검증, 공격 반응, 무효화, 버프 중첩, 일체화 재진화, 전체 장착 효과는 후속 작업이다.
3. AI는 서버의 비공개 적 카드 정보를 판정·난수용으로 접근하지만 전략 선택에서 손패 정보를 사용하지 않도록 해야 한다. 명시적으로 공개된 카드만 평가하는 테스트가 추가로 필요하다.
4. 서버는 단일 Node 프로세스와 파일 저장을 전제로 한다. 영속 데이터 DB, 요청 동시성, 장애 복구와 공개 배포 시 보안 점검은 별도의 과정이다.
5. 룰북/카드 데이터 버전은 `1.3` 기준이지만 엔진의 베타 자동화 버전은 `1.3-ai-beta.1`이다. 버전 고정·마이그레이션을 테스트해야 한다.

## 개선 순서

1. 전체 254개 카드별 요구사항 표 작성 → 미지원/부분 지원/검증 완료를 카드별로 표시.
2. 사건-발동 조건-비용-효과-복구/지속 객체의 범용 엔진과 효과 스택 구현.
3. 퓨전·라피드·얼라이즈, 조종권·장착·토큰 등 구조적인 특수 처리 구현.
4. UI의 효과별 대상으로 선택할 카드·영역·선택지를 정확히 요청하고 입력 불가능 상황 차단.
5. 24개 덱의 모든 동일/서로 다른 대전 조합 및 수천 회 시뮬레이션·고정 난수 테스트.
6. 단일 Node 개발 서버를 DB·재연결·관측·레이트 제한이 있는 운영 환경으로 옮긴 뒤 공개 베타.
