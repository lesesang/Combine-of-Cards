## 이번 범위

금속 생명체 연성술06-002, 스토밍 마인드14-002, 스톰 블레이거 나이트14-004, 스톰 팬니르14-005, 스톰샷14-009의 토큰 모드, 미라 군사 소환17-004의 **6개 토큰 생성 경로**와 파프니르11-007·황금11-008을 같은 직렬 처리에 연결했다. 기존 주문/몬스터 효과 해결은 토큰 생성 작업을 기록하며, 그 함수 안에서 상대의 대응 스택을 다시 실행하지 않는다.

순서는 다음과 같다.

1. 다음 토큰의 빈 필드 확인 → 토큰 소환 선언 → 별도 소환 대응.
2. 성공한 경우에만 토큰을 실제 필드에 놓고 생성/소환 사건 한 개를 기록.
3. 사건 당시 패/덱의 파프니르 후보를 모아 공통 자동 선언 순서를 선택하고 역순으로 각각 소환 대응.
4. 성공한 파프니르의 기존 생성 유발 대응 → 황금/반지 실물 생성 → 황금의 패 진입 자동 주문 대응.
5. 해당 사건을 받을 활성 황금을 하나만 골라 보물 추가, 아직 같은 필드 체류에 있는 토큰이면 비파괴 전환.
6. 그 뒤 다음 토큰의 빈 칸을 다시 확인.

따라서 다수 토큰을 먼저 전부 배치해 파프니르가 쓸 마지막 칸을 막지 않는다. 빈 칸을 미래 소환에 미리 부여하거나 네 번째 필드를 만들지 않는다. 한 칸밖에 없어서 성공한 토큰이 마지막 칸을 차지했다면 그 사건의 파프니르는 소환할 수 없다. 황금이 무효화되면 토큰이 남아 다음 토큰을 위한 칸이 부족해질 수 있다.

생성 수·기본 ATK/HP·인조 생물의 기존 원소/금속 사용 수 계산·기존 비용은 유지한다. 복수 소환에서 무효화된 한 토큰 때문에 이후 토큰까지 자동 취소하지 않는다. 각 남은 작업은 실제 빈 칸에서 개별 시도한다.

## 소환 선언과 실제 사건

`token-pipeline.mjs`는 JSON 작업/사건 대기열을 사용한다. 소환 선언 때 만든 임시 토큰 UID는 플레이어의 패·덱·묘지·필드에 넣지 않고 대응 화면에만 공개한다. 성공 시 실제 필드에 배치한다. 무효/빈 칸 소실이면 임시 UID를 폐기하고 실제 생성/소환 사건이나 보물을 만들지 않는다. 항복/종료에도 미배치 임시 토큰을 정리한다. 이 임시 상태를 새 카드 원본이나 실제 소환 성공으로 취급하지 않는다.

R05대로 생성/소환의 한 번의 필드 진입은 한 사건이며, 나중에 실제 비용으로 사용/릴리스하면 별개 사건이다. 기존 일반 발동·재사용 비용의 `tokenAction`, 파괴 비용의 `cause:cost`에서 실제 필드 이탈 후 사건을 기록한다. 비용 파괴 경로는 이동 함수와 중복 계수하지 않는다. 일반 파괴/단순 반환을 사용/릴리스로 새로 해석하지 않는다.

전환은 토큰 UID·조종자·필드 체류가 그대로인 경우만 실제 제거한다. 이미 떠난 토큰이나 같은 칸에 들어온 다른 카드를 제거하지 않는다. 사건 자체가 이미 발생했으면 원래 토큰이 이후 이동했더라도 사건의 보물 적립은 판정한다. 보물 전환은 파괴/릴리스/새 토큰 사건이 아니며, 기존 이동 함수의 몬스터 제외 손실 이력에도 기록하지 않게 분리했다.

## 파프니르: 여러 실제 카드와 원래 영역

각 사건에 존재한 패/덱의 실제 파프니르 UID·보유자·영역·영역 체류 번호를 저장한다. 후보 목록은 덱 순서 대신 UID 순서로 수집하고, 같은 우선도에 여러 선언이 있으면 기존 자동 순서 UI를 사용한다. 현재 턴 플레이어 먼저 선언하고 역순 해결하는 공통 규칙을 유지한다. 소환 직전과 해결 시 원본/체류/빈 칸/사용 가능 상태를 확인한다.

기존의 ‘그 플레이어에게 황금이 이미 있으면 다른 파프니르를 검사하지 않음’ 제한을 제거했다. 별개 실물의 조건을 검사하며 같은 실물을 같은 사건에서 두 번 소환하지 않는다. R22 및 사용자 확정대로 소환 무효 시 패/덱에 그대로 남고 이미 지불한 다른 카드의 비용은 반환하지 않는다.

성공 후 `H.onSummon`을 통해 카드 사용/소환 이력과 기존 파프니르 생성 유발을 기록한다. 생성 유발은 원본 필드 체류·무효 상태·실물별 효과1 턴 제한을 적용한다. **소환 무효**와 **몬스터 생성 효과 무효**는 별개다. 라이징 윈드 걸은 생성 효과에 대응할 수 있으며 소환 자체에는 대응하지 않는다.

## 황금: 패 유입 자동 사용과 중복 방지

파프니르의 생성 효과가 황금/반지의 연결을 먼저 저장하고 두 카드를 패로 보낸다. 이제 황금은 즉시 지속 상태를 등록하지 않고 자동 사용을 대기한다. 공통 `move(...,'hand')`뿐 아니라 `draw()`의 패 유입에도 연결했다. 원본 UID·패 체류·소유 연결을 기록하고, 여러 황금이 같은 처리에서 대기하면 공통 자동 선언 순서/역순 해결을 사용한다.

실제 사용 시 원본이 같은 패에 있고 주문 금지/실물별 효과1 사용 제한에 걸리지 않아야 한다. 원본을 원래 소유자의 묘지로 보내고 사용 이력·턴 주문 수·실물별 사용 횟수를 기록한 뒤 별도 주문 대응을 받는다. 대응 창은 기존 `pendingAbility`의 `gold-cast` 종류이며, 스톰블레이거/블래스트/디텍티브의 주문 무효 범위다. 윈드 걸은 황금 자체에 대응할 수 없다. 상대 몬스터가 선언한 무효화에 대한 윈드 걸의 후발 대응은 기존 공통 분류대로 가능하다.

해결 시 사용한 황금의 같은 묘지 체류와 생성 당시 파프니르의 필드 체류를 확인한다. 처음 성공하면 독립 지속 효과를 등록한다. 같은 실물의 기존 지속 효과가 있으면 보물 수를 초기화하거나 추가 인스턴스를 만들지 않는다. 새로운 실제 황금은 별도 상태를 가진다. 기존 활성 황금이 다시 패에 들어와 사용되었을 때 그 사용이 무효화되어도 먼저 적용된 독립 효과를 해제하지 않는다.

최초 사용이 무효화되면 새 지속 효과를 적용하지 않고 사용한 카드는 묘지에 남는다. 주문 금지나 이번 턴 사용 제한으로 자동 사용하지 못했다면 패에 남고, 금지가 풀렸다는 이유만으로 놓친 패 진입 사건을 재생하지 않는다. 이후 새 패 진입 사건을 다시 판정한다. 생성 연결을 알 수 없는 과거 저장 카드에 임의 파프니르/반지를 지어 붙이지 않는다. 과거 활성 지속 상태가 있으면 그 연결 정보만 사용한다.

R06의 조종자 측 우선/사건당 하나 적립을 유지한다. 같은 쪽에 활성 황금이 여러 개라면 **가장 먼저 적용된 활성 황금**에 적립하도록 개발자 명확화했다. 다른 황금의 어택 시작 +5는 기존 독립 효과대로 별개다. 반지의 저장 보물 보상/황금 종료/플레이어 버프 및 마검 지불 불가 즉시 패배는 앞선 구현을 유지한다.

## 부모 대응·선택·AI·저장

토큰 비용으로 발생한 연계가 원래 카드의 소환보다 먼저 빈 칸을 사용할 수 있으므로, 원래 카드의 `pendingAbility/pendingSpell/pendingExtraSummon/pendingMonsterTriggers`와 효과 스택을 기존 보관 프레임에 넣는다. 연계가 끝나기 전 그 부모 프레임을 복원하지 않는다. 묘지 사건의 별도 상위 프레임은 기존 방식으로 복원하며, 스택 자체를 이동 훅 안에서 실행하지 않는다.

턴 시작/종료, 강제 턴 종료, 다음 부활/연속 소환, 다음 전체 공격, 재단 첫 발동은 토큰 작업이 끝나기를 기다린다. 처리 중 외부의 새 일반 행동도 막는다. 황금 자동 사용·토큰/파프니르 소환·동시 선언 순서는 기존 PvP 대응/선택 UI와 AI3난이도의 공통 합법 카운터/선택 경로를 사용한다. UI에 토큰/파프니르 자동/일반/연속 소환을 구분하고 무효 결과를 표시했다. AI 전술 품질이나 대전 완주를 검증했다는 뜻은 아니다.

작업/사건/선언 큐·소스 체류·부모 프레임은 함수나 Map을 저장하지 않는 JSON 상태다. 같은 작업은 큐에서 제거한 뒤 사건을 전달하여 중복 재개 시 재적립하지 않게 구성했다. 기존 서버의 요청 롤백/방 저장을 사용한다. 재접속·동시 요청 및 실제 D1 트랜잭션의 동작은 아직 실행 검증하지 않았다.
