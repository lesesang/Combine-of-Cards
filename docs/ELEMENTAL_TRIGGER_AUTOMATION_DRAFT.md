# 원소 유발 자동화 구현 묶음 — 검증 전

기준 main `43b72d0` / PR #74. 사용자가 **“지금부터는 일단 자동화만 해줘. 테스트는 나중에 한 번에”**라고 변경했다. 이 작업은 구현 브랜치/draft PR에 모으며 테스트·CI 실행·main 병합·배포를 보류한다. 기존91건 효과 증거와555개 통과 기록은 PR #74의 기준선일 뿐, 이 변경의 검증 결과가 아니다. 효과 증거 보고서에 미검증 구현을 새 증거로 등록하지 않는다.

## 작성한 자동화 경로

| 카드 | 새 코드 경로 | 상태 |
|---|---|---|
| 워터 COC-32-002 /2 | 상대 몬스터의 공격 대상 선언/재선택 → UID별 효과2 턴1회 → 윈드 걸 대응 → 공격자 실제ATK > 워터HP면 파괴. 파괴 후 부활해도 이전 공격 종료 | 구현, 미검증 |
| 랜드 COC-32-004 /2 | 필드 체류 중 현재 조종자의 두 번째 턴 시작 → 같은 시점 여러 랜드 선언 순서 선택 → 대응/LIFO → ATK/HP 교환 | 구현, 미검증 |
| 인피니티 COC-32-015 /1 | 공격 선언 → UID별 턴1회 → 대응 → 상대 패 무작위2/덱 위2 제외 → 상대가 자기 묘지에서 최대2장 선택 → 공격 대응 재개 | 구현, 미검증 |

`src/triggered-effects.mjs`가 세 유발을 명시적으로 등록한다. `pendingMonsterTriggers`에 선언 순서와 효과 스냅샷을 JSON으로 보관하고 후발부터 하나씩 기존 `abilityResponse`에 연결한다. 윈드 걸은 세 몬스터 유발과 그 카운터에 대응하며, 주문/일체화/소환으로 범위를 넓히지 않는다. 기존 비용/횟수 예외도 바꾸지 않는다.

랜드 체류는 테라와 같은 `dragonResidence` 기록을 사용한다. 필드 조종권 이동은 유지하고 영역 이탈은 초기화한다. 두 번째 시작에 무효 상태였다면 그 체류의 기회를 나중에 다시 발생시키지 않는다. 선언 후 무효화되어도 그 체류의 교환을 재시도하지 않는다. `pendingTurnStart`로 기존 턴 시작 후속 처리와 정상 드로우를 유발 해결 뒤까지 기다리게 한다.

인피니티는 상대의 패 내용을 선택 UI/로그로 공개하지 않고 서버에서 무작위로 고른다. 덱 위 카드는 순서대로 처리하며 부족하면 존재하는 수만 제외한다. 묘지 선택은 상대 플레이어 권한으로 `infinityGraveChoice`에 연결한다. 선택 중 일반 행동/패 열람/진화 비용 열람을 잠그고 UID 중복/영역/요구 수량을 검사한다. 하·중·상 AI의 자기 묘지 선택과 사람의 대응 대기를 연결한다. 승패/항복 시 대기 상태를 정리한다.

## 개발자 판단과 남은 통합

- 워터는 공격 대상으로 지정되면 자동 선언하고 그 순간 횟수를 사용한다. 공격력 부등식은 해결 시 검사한다. 재선택된 워터도 대상 선언으로 취급하지만 인피니티의 공격 선언 효과는 재선택만으로 다시 발생시키지 않는다.
- 인피니티의 ‘최대2장’은 각 영역에 존재하는 수와2 중 작은 수만큼 처리한다. 묘지 선택을0장으로 임의 회피하는 선택은 제공하지 않는다. 필드/일체화는 제외하지 않는다.
- 랜드의 교환은 변경 가능한 ATK/HP 층에서 수행하고 독립 마검 배율은 유지한다. 예를 들어 변경 가능한ATK100·HP230·독립×2이면 교환 뒤 ATK층230·HP100이며 표시ATK460이다. 이는 기존 매치 계열의 능력치 설정과 일관된 **개발자 해석**이며 사용자 개별 확정으로 주장하지 않는다. 마검의 기간/지불/중첩 재정은 그대로다.
- 랜드 유발을 기존 드로우 시점 자동 처리보다 먼저 해결하도록 후속 처리를 보관했다. 다른 모든 턴 시작/파괴 유발까지 하나의 동시 사건 그룹으로 통합한 것은 아니다.
- 새 유발들은 원소1번 교체와 공용 제한을 공유하지 않는다. 원소 교체를 임의 체인 중 추가하는 범용 후발 삽입은 계속 남는다.
- 이번 코드는 실행 검증하지 않았다. HTTP 복구/동시 유발/카운터/비공개/AI/승패·후속 처리의 실제 정상 동작과 기존 회귀 영향은 후속 일괄 검증에서 확인해야 한다.
