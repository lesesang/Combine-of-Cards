## 재사용의 원본·실행자·대상 분리

`src/spell-reuse.mjs`는 `usedCardsGame`의 실제 사용 기록에서 원본 카드 ID·당시 사용자·물리 UID를 고른다. 원본을 소모하거나 임의 카드 복제본을 만들어 패/묘지에 넣지 않는다. 원본이 지금 이동했어도 과거에 사용했던 효과를 선택할 수 있다. 구 저장에 이력이 없으면 현재 묘지나 공개 로그로 사용 이력을 추측하지 않는다.

별도 `reuseSpell` 행동과 `pendingAbility(kind: reuse)`를 사용한다. 선언 때 원본 식별, 실행자/일체화 세대, 선택 대상/조종권/체류 세대를 JSON으로 저장한다. 해결 때 실행자 이탈/진화/무효 또는 대상 이탈/재진입을 확인한다. 원본 카드를 현재 위치에서 다시 발동시키지 않으므로 원본 UID의 횟수와 영역은 바뀌지 않는다. 합법성 실패는 비용/횟수 소비 전에 거부하고 선언 중 실패는 스냅샷으로 되돌린다.

하우스 파티는 주문이므로 스톰블레이거·블래스트 보이·해당 디텍티브의 주문 무효화 대상이다. 아젤리아/유리카·베리아/스트로베리아는 일체화 효과이므로 윈드 걸의 몬스터 효과 무효화 대상이 아니다. 퓨전 업의 묘지 주문 효과 역시 주문 효과로 대응한다. 스톰의 기존 게임1회 통합 횟수, 필드 카운터의 재소환 초기화는 유지한다. 주문 사용 금지는 재사용과 묘지 주문 발동에도 적용한다.

UI의 **주문 재사용** 메뉴에서 실행자·원본·대상을 고른다. 실제 사용했지만 아직 지원하지 않는 주문은 별도로 이름을 표시하고 실행을 막는다. 하우스 파티는 일반 패 사용 대신 이 메뉴로 사용한다. AI도 같은 합법성 검사와 API를 사용하며 하 난이도는 합법 후보 무작위, 중/상은 공개 수치 중심으로 선택한다. 난이도 품질이나 승률은 아직 검증하지 않았다.

## 다이스·추가 드로우 수정

- 피해·회복 수치 다이스를 `rollValue`로 분리했다. 보통은 원래 최댓값 + 무리의 집결 누적 증가분, 아젤리아/유리카 재사용 해결 중에는 **100 + 누적 증가분**이다. 전역 다이스 함수를 바꾸지 않으므로 다음 일반 주문/공격에 임시100이 남지 않는다.
- 버스트는 한 번 굴린 같은 값을 양쪽에 적용한다(R25). 말벌은 각각 독립해서3회 굴린다. 코인의 앞/뒤 판정 및 비용 수량 판정은 수치 피해/회복 다이스와 구분해 1d2/1d5를 그대로 유지했다. 이는 창작 의도를 보존하는 개발자 해석이며 새로운 사용자 확정으로 기록하지 않는다.
- 말벌 대상은 한 번 확정한다. 첫 피해로 대상이 사라졌을 때 다음 타격이 없는 대상을 다시 찾으며 전체 해결을 실패시키던 문제를 고쳤다. 대상 이탈/재진입 후에는 새 대상에 나머지 피해를 돌리지 않는다.
- 무리의 집결을 여러 번 해결하면 +50과 다음 자기 턴 추가 드로우를 각각 누적한다. `bonusDrawsByOwnTurn`에 장수를 기록하며 구 저장의 `bonusDrawOnTurn` 예약1장도 별도로 존중한다. 일반 드로우/리로드/승패 처리를 사용한다.

## 묘지 이동 자체와 효과 발동 사건 구분

`recordGraveEffectActivation`은 명시된 효과 선언 또는 묘지 후보 선택에서만 호출한다. 공통 `move`에 무조건 붙이지 않았다. 따라서 리로드·단순 버리기·수동 이동·소재를 묘지로 보내는 것만으로 베리아가 발동하지 않는다. 같은 효과로 여러 카드를 옮겨도 한 사건이며, 서로 다른 발동은 같은 턴이어도 각각 사건이다. 이벤트 키로 중복을 방지하고 양쪽의 유효한 베리아 계열이 각각 반응한다.

현재 연결한 경로:

- 선언 때 묘지 이동이 정해진 경로: 퓨전 업 효과2, 케미, 백귀야행, 메디컬 타임, 묘지의 카드를 찾는 퇴마부. 인피니티는 상대 묘지에 후보가 있을 때 유발 선언에서 연결한다. 이후 원래 효과가 무효화되어도 발동 사건 자체는 취소하지 않는다.
- 선택 후에 묘지 사용이 정해지는 경로: 버닝소울·최후의 희망의 묶음에서 묘지 후보가 포함되면 전체 선택에1회, 슈/원소4종은 묘지 후보를 확정할 때1회. 패·덱 후보만 사용하면 사건을 만들지 않는다. 이미 무효되어 선택까지 도달하지 않은 효과는 묘지 사용을 추측하지 않는다.
- 조건 성립 뒤의 회수: 독거미 쇄도30-004의 해당 피해 처치 후 패 회수, 웨이크업 드래곤32-009의 END 묘지 회수. 현재 묘지에 실제 원본이 있을 때만 연결한다. 카드 이동 횟수를 추가로 중복 계산하지 않는다.

베리아의 강화·스트로베리아의 선택은 등록된 일반 선언/소환이 해결되기 전에 실행해야 한다. `suspendedResponses`는 진행 중인 대응/스택/남은 유발 큐를 JSON으로 보관하고 새 유발을 먼저 해결한 뒤 부모 대응으로 돌아온다. 예를 들어 묘지 부활 선택에 반응한 베리아의 +50이 부활 몬스터의 진입 스냅샷보다 뒤로 밀리지 않게 한다. 선언/해결에 의존하는 유발과 일반 무효화의 전체 조합은 후속 검증 대상이다. 깊이32의 안전 한도를 넘으면 승자를 임의 결정하지 않고 오류로 중단한다.

END 회수 유발을 잃지 않도록 `pendingTurnEnd`로 턴 넘기기를 보류한다. 회수 반응·선택이 끝난 뒤 필드 점유 이력과 마검 턴 종료를 처리하고 다음 턴을 시작한다. 공격자는 영역/체류 세대도 기록하여 스트로베리아 등으로 파괴되어 묘지에 있는 공격자가 계속 공격하거나, 재소환된 카드가 이전 공격을 이어가는 것을 막는다.

## 위임 해석 및 실질적 미완료

- 아젤리아/유리카는 자신의 사용 이력, “이 게임에서 사용된” 하우스 파티는 양쪽의 사용 이력을 참조한다. 하우스 파티의 “딱1회”는 해당 물리 카드 게임당1회로 두어 회수 루프를 막고 서로 다른 실제 카드는 구분한다.
- 재사용은 실행자 관점으로 현재 보드/그 실행자의 기존 이력을 읽는다. 원본 실행 때의 과거 피해량·주사위 결과를 그대로 재생하지 않는다. 선택한 원본 식별과 발동 대상은 선언 스냅샷이다. 원죄의 별도 과거 기록 복사 규칙과 혼동하지 않는다.
- 베리아 계열의 “할 때마다”는 명시적 반복 예외로 처리한다. 스트로베리아의 “할 수 있다”는 선택적 파괴이며 UI/AI 모두 생략할 수 있다. 새 사용자 확정은 아니다.
- 조건부·선택형 효과의 사건 발생 시점은 위의 명시 목록에 한정된다. 아직 묘지 소재 퓨전 자체가 지원되지 않는 경로, 이모탈/아스클레피오스 등 나머지 자동 부활, 모든 토큰/장착, 범용 복사는 완료하지 않았다.
- 기존 도깨비불의 모든 지속 만료·조종권 변화, 전역 동시 피해/리로드, 전체 체인의 임의 삽입을 이 묶음으로 완성했다고 주장하지 않는다. 재사용 메뉴는 기존 기본 효과를 연결한 범위이며 기존 부분 구현의 한계도 남는다.
- 추가 상태는 JSON이며 D1 계획과 양립하도록 작성했다. 개인 D1 연결·다중 쓰기/CAS·운영 배포는 아직 없다. 누락된 v1.3 DOCX/정본을 생성하지 않았다.

## 후속 일괄 검증과 다음 묶음

**현재 실행하지 않음:** 기본22종의 재사용 원문/대상/수치·원본 미소모, UID/효과2/게임1회, 무효 후 횟수, 소스/대상 재진입, 재사용 비지원 거부/원자성, 코인·공유/독립 다이스·누적 드로우, 사용 이력/구 저장/비공개, 묘지 발동과 이동 구분·무효된 선언·반복/양쪽 반응·선택 생략, 부모 스택 보관/복구·동시 순서·END·공격 취소, HTTP/재접속 및 AI3난이도를 일괄 검증해야 한다. 묘지 회수의 기존 즉시 해결 테스트도 새 대응 절차로 바꿔야 한다. 생성 보고서 및 Node tests·Verify TCG beta가 통과하기 전 병합하지 않는다.

다음은 재사용의 비용·물리 원본 이동/진화/소환 연속 처리 확장, 원죄의 별도 복사 규칙, 미연결 부활 사건, 실제 무기 장착·기간이다. 문서/이슈 갱신은 해당 구현 묶음마다 한 번에 진행한다.
