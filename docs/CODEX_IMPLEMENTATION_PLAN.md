## P0. 즉시 착수할 PR 크기 작업

### P0-1. 정본 확보·버전 관리 (#21, #23) — 원본 있으면 최우선

**입력:** 이전 대화 생성 v1.3 DOCX/Markdown/JSON, `03_카드_데이터_v1.3.json`과 구버전 비교 근거. GitHub에는 현재 없음. Codex는 사용자 승인·소유권 확인 없이 외부 자료를 훔쳐오거나 구버전을 정본이라고 조작하지 않는다.

1. 원본의 안전한 입수/권리 확인. `docs/SOURCE_DATA_PROVENANCE.md` 목록 기준으로 파일명·해시·생성시각·출처 기록.
2. 가능하면 `data/source/v1.3/` 등 버전화된 비개인정보 텍스트/JSON 저장. 삭제 8덱, 24덱, 254개 COC-ID, 인쇄 수치/종류/조건/효과 원문/효과 번호 테스트.
3. `scripts/build-data.mjs` 변환 및 **`public/data/catalog.json.gz.b64` 재생성**. 서버가 JSON보다 압축 카탈로그를 우선 읽는다는 점 검증.
4. 기계 diff: v1.3 원본 → 런타임 카탈로그, 덱별 카드 집합, 소환 레시피, 누락 효과 문장, 변경 내용. 룰북/정본/압축 버전 불일치 시 CI 실패.
5. **원본이 현재 확보되지 않으면** 그 사실과 막힌 지점을 #21에 명시하고 아래 P0-2/P0-3·출처 독립 테스트로 진행한다. 정본 존재를 거짓 주장하지 않는다.

**수락:** 출처·권한/공개 범위 문서, ID·효과 번호 기반 diff, 24/254/삭제 덱 보호, 서버 실제 로드 데이터 대조, PR 두 CI 성공.

### P0-2. 공통 이벤트/대응 체인 최소 종단간 완성 (#22, R01/R02/R22)

현재 `src/effect-runtime.mjs`가 JSON 가능한 LIFO, 원자적 단일/그룹 선언·해결, 동시 트리거 순서 선택의 일부를 지원한다. `server.mjs`의 `pendingSpell`/`pendingExtraSummon`은 **상대가 pass하면 진행**되는 제한된 응답 창이다. BLOCK의 선택 패 비용은 대응 전에 지불하고 무효화 시 반환하지 않는다. 스톰블레이거의 16종 주문 무효화 경로는 서버/UI/AI/복구에 연결했다. 소환 무효화와 다른 카드의 범용 체인은 미완성이다.

**작은 PR들의 권장 순서:**
1. 이벤트 타입/식별자와 안정된 소스·이전 상태: activation, COST_PAID, SUMMON_REQUEST, DESTROYED, ZONE_MOVED, ATTACK_DECLARE, DAMAGE, 턴 시작/종료. 위상별 중복 기록 방지.
2. **첫 대응 카드 스톰블레이거의 주문 절은 부분 구현**했다. 다음 실제 카운터/무효화 카드를 근거 문구로 고르고 선언→비용→대응 선택→효과 스택→무효/성공 해결. 비용 원자성/상대 비밀정보/소스 이탈/연쇄 시작 모두 검사.
3. 첫 카운터를 PvP UI와 AI 모두에서 똑같은 합법 행동 API로 제공. 상대가 응답 안 하면 pass, 응답하면 카드별 비용·우선순위. 중간 저장/재접속해도 동일 단계 복원.
4. **R22 소환 무효화**를 위 상태 기계에 연결; 비용/소재는 상대 응답 전에 지불, 무효돼도 반환하지 않음. '즉시 소환' 또는 비용 뒤 조용히 취소는 금지.
5. 필드/묘지/파괴·지속·복사 발동을 단계적으로 같은 체인에 연결; **후발 우선**, 동일 우선도 현재 턴 플레이어 선언순 선택/상대 선언순 선택 보존.
6. 동시 발동·순환·응답 중 카드 위치 변경·코스트를 이미 지불한 상태에서 불법 요청·서버 저장/복구를 사건별 테스트.

**수락:** 실제 서버 행동 + UI + AI를 거치는 **성공/무효 2경로**; 원본 비용 반환 여부; JSON 직렬화/버전 검사; 테스트 없이 "모든 체인 완료" 선언 금지.

### P0-3. 254장 전 효과 번호 인벤토리 (#23/#25, R03/R27)

**2026-10-13 후속:** 공유 응답 주문 레지스트리의 16종 집계, 잘못된 등록/문서 불일치 CI 검출, R28/R29 확정 회귀 증거 정합성을 보완했다. 전 카드 원문·효과 인벤토리는 계속 미완료이며 다음에는 확보된 원문 범위에서 효과별 명세와 증거를 확장한다.

1. 현재 `docs/effect-coverage.json`은 **8건**만 등록. 카탈로그 카드의 각 효과 텍스트와 원본 조건을 기준으로 **카드 ID+효과 번호**를 나열한다.
2. `trigger / condition / cost / target / resolution / duration / remaining / implementation / tests` 형식을 준수한다. 진짜 미구현 효과는 **미등록·미지원**으로 표시하거나 지원 상태 스키마를 확장하고, 실제 테스트가 없는 효과를 partial로 허위 등록하지 않는다.
3. 효과 번호 하나마다 사람·AI·경계/불법/예외·데이터 변경·대응/소스 이동·승패 테스트를 만든다. 완료된 조항만 인증.
4. 자동 생성 파일 `docs/AUTOMATION_COVERAGE.md`, `docs/automation-audit.json`, `docs/EFFECT_COVERAGE.md`는 `npm run check:coverage`로 재생성 후 `--check` 검증. 사람이 쓴 해설은 `docs/AUTOMATION_NOTES.md`.
5. 각 PR에서 카드별 partial/manual/basic 수치가 변하면 **README·인수인계·런북·AGENTS 등 고정 수치를 갱신**하고 CI에 일치 검사 도입.

**수락:** 모든 카드에 미지원 효과가 무엇인지 확인 가능, 실제 증거 링크, 오래된 생성 보고서/없는 테스트/완료 허위 표시의 CI 실패.

## P2. AI·검증 (#27/#28)

1. AI가 “미지원 주문 건너뛰기”가 아니라 **합법 행동 열거**에 의해 모든 카드 행동·비용·선택·대응 수행. 하/중/상 간 전략 차이, **같은 서버 검증기** 사용.
2. 단일 seed를 저장해 덱 셔플·코인/전투 다이스 등 서버 RNG 및 사건의 재현 가능성/로그 추적. **현재의 AI 24덱 스모크는 576게임 완주 검증이 아님**.
3. 매치 **24×24=576** 방향성 있는 덱 조합(자기 자신과의 매치 포함), 양쪽 선후공/난이도/복수 seed로 테스트. 완료 기준은 **종료/합법성/보안**이며 단지 에러가 없는 것이 아님.
4. 엔진 불변식: 카드 UID 존재·원소유자·현재 조종자·정확히 한 물리적 영역·겹침·장착·턴 사용횟수·HP/승패·중복 비용·버전 충돌/재전송·금지 행동이 실제로 거부되는지.
5. 무한 반복은 상태 변경 중 정상 반복과 동일 상태 순환 분리. 유효한 반복에 임의 70단계 규칙/256 스택 룰 덧씌우지 않으며 서버 안전 상한은 보호 장치로만 표기.
6. 동시 파괴/승패·실제 공격력·마검 2ⁿ·AI 숨김 패 노출/상대 패 확인 허용 예외 등 악의적 연쇄 검사.

## 1개 PR마다 반드시 실행할 완료 절차

```bash
npm test
npm run check:data
npm run test:matrix
npm run check:coverage
npm run check:coverage -- --check
```

1. **최신 main**에서 작업 브랜치 생성; 이슈와 해당 카드 효과 번호를 고정.
2. 실패하는 정확한 회귀 테스트를 먼저 작성, 서버·AI·UI 모두 변경 범위를 확인.
3. 생성된 출력과 사람이 쓰는 원문/재정 문서를 분리해 갱신.
4. Node tests와 Verify TCG beta가 **최종 브랜치 SHA**에서 성공함을 확인하고 PR 병합.
5. 병합 후 **main CI 성공** 확인. 실패하면 원인 확인·보완. 테스트 약화/무조건 pass 금지.
