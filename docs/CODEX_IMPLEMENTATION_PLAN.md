## 사용자 변경: 구현 우선, 일괄 검증은 후속 단계 (2026-10-15)

사용자가 “지금부터는 일단 자동화만 해줘. 테스트는 나중에 한 번에”라고 지시했다. 현재 구현 단계에서는 테스트/CI를 실행하지 않고 별도 브랜치·draft PR에 모은다. 커밋의 `[skip ci]`로 자동 CI 실행도 보류하며 테스트 자체를 삭제하거나 약화하지 않는다. 기존의 최종 검증/병합 절차는 후속 일괄 검증 단계에 적용한다. 미검증 변경을 완료 인증/CI 성공으로 표시하거나 main에 병합·배포하지 않는다. 이 최신 사용자 요청이 아래 과거 작업별 즉시 테스트 지침보다 우선한다.

현재 구현 브랜치: [원소 유발/조건](ELEMENTAL_TRIGGER_AUTOMATION_DRAFT.md) + [진화·소환 연계19종 구현 초안](EVOLVED_AND_SUMMON_AUTOMATION_DRAFT.md)을 draft PR #75에 추가했다. 진화 사용 이력3종, 선택 부활/소환4종, 드라고닉·지니어스 발동, 소환 유발6종, 버닝 드래곤·야시키·지연 파괴·매치 반사를 작성했다. 일반 패 몬스터 소환도 비용→대응→소환으로 연결했다. **테스트/CI 미실행, 미병합**이다. 새 등록 목록은 주문76/대응68·필드22·몬스터 유발12이며 검증 인증 수치는 아니다. 생성 보고서는 PR #74의 기준선으로 남겼고 일괄 검증 때 갱신해야 한다. 다음은 묘지 이동 발동·회수·복사·장착과 남은 소환/유발이다.


**대상:** `lesesang/Combine-of-Cards`, 2026-10-14 / 필드 무효화3종·윈드 걸 몬스터 효과 대상 정정, v1.3 원본 규칙. 이 문서는 **미구현 기능을 전부 구체적인 개발 작업으로 쪼개는 계획**이며 완료 선언이 아니다. 원본 확정 판정은 `CODEX_RULES_REFERENCE.md`, 현재 범위는 `CODEX_HANDOFF.md`, 상세 제품 완성 기준은 `ROADMAP_AND_ACCEPTANCE.md`, GitHub 이슈는 #21~#29.

## P2. AI·검증 (#27/#28)

1. AI가 “미지원 주문 건너뛰기”가 아니라 **합법 행동 열거**에 의해 모든 카드 행동·비용·선택·대응 수행. 하/중/상 간 전략 차이, **같은 서버 검증기** 사용.
2. 단일 seed를 저장해 덱 셔플·코인/전투 다이스 등 서버 RNG 및 사건의 재현 가능성/로그 추적. **현재의 AI 24덱 스모크는 576게임 완주 검증이 아님**.
3. 매치 **24×24=576** 방향성 있는 덱 조합(자기 자신과의 매치 포함), 양쪽 선후공/난이도/복수 seed로 테스트. 완료 기준은 **종료/합법성/보안**이며 단지 에러가 없는 것이 아님.
4. 엔진 불변식: 카드 UID 존재·원소유자·현재 조종자·정확히 한 물리적 영역·겹침·장착·턴 사용횟수·HP/승패·중복 비용·버전 충돌/재전송·금지 행동이 실제로 거부되는지.
5. 무한 반복은 상태 변경 중 정상 반복과 동일 상태 순환 분리. 유효한 반복에 임의 70단계 규칙/256 스택 룰 덧씌우지 않으며 서버 안전 상한은 보호 장치로만 표기.
6. 동시 파괴/승패·실제 공격력·마검 2ⁿ·AI 숨김 패 노출/상대 패 확인 허용 예외 등 악의적 연쇄 검사.

**수락:** 576 덱 조합 + 다중 시드/선후공/난이도/재접속 케이스의 로그/합법성 검증, 보안 정보 누출 0, 심각한 미해결 판정 충돌 0.
