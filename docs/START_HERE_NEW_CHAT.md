## 2026-10-13 추가 확정 — 생명을 먹는 마검 공격 페이즈·다음 자기 턴 중복 (PR #58)

5. **docs/ROADMAP_AND_ACCEPTANCE.md** — 전체 자동화·AI·안전성·운영까지 우선순위/완료 기준.
6. **docs/OPEN_RULINGS_REGISTER.md** — 아직 확정되지 않은 해석·충돌과 현재 임시 코드 처리. **확정 재정과 혼동 금지.**
7. **docs/ARCHITECTURE_AND_RUNBOOK.md** — 파일 구조, 실행, 빌드, 테스트, 배포·보안 제한.

별도 Word 파일로 만들어진 2026-10-12 **v1.3 통합 룰북·24개 덱 카드집·원본 비교 JSON**은 과거 대화에서 생성되었지만 **현 저장소에는 그 정본 파일 자체가 커밋되어 있지 않다**. 현재 repo에는 압축되어 변환된 플레이용 카드 도감(public/data/catalog.json.gz.b64)이 들어 있다. 원본 v1.3 JSON/DOCX를 정본으로 버전 관리하는 작업은 **최우선 후속 과제**이다. 여기서 공개 플레이 도감 데이터를 원본 전체 명세와 동일하다고 추정하지 말 것.

## 2. 실제 구현된 사이트

- Node.js 20+ 표준 라이브러리 서버와 정적 한국어 UI; 덱/카드 도감·검색·규칙 안내.
- 2인 대전방, 비밀 토큰 인증, 방 코드, 서버 난수 셔플/드로우/다이스/승패, 손패 비공개, 단일 프로세스 파일 저장.
- AI 1인 대전: 유저 덱 선택, AI 상대 덱 지정·랜덤, 하/중/상 규칙 기반 휴리스틱 AI.
- 소환·일체화·기본 공격·리로드·공격 선언 시 대응 확인·상대 대응으로 대상 소멸 시 재선택.
- 일부 주문 ID별 핸들러, 몬스터 소환/필드 발동/특수 전투/엑스트라 소환 소재 검사 및 일부 지속 트리거.
- JSON 직렬화가 가능한 효과 스택 기반 모듈(src/effect-runtime.mjs): LIFO, 필드 이탈 일반 효과 무효 및 확정된 예외, 독립 지속 효과. **모든 카드 발동에 전역으로 적용된 범용 체인은 아직 없음.**
- 용·드래곤 파프니르 → 라인의 황금 → 니벨룽겐의 반지 부분 연계, 카툰 랜드 파괴 연쇄 및 복구 등.
- 양 플레이어가 별도로 확인한 수동 판정을 수행할 수 있으나 **수동 승인 = 룰 합법성 인증 아님**. AI 모드에서 미지원 주문을 조용히 소모하지 않는 방향으로 방어.

## 3. 현재 가장 큰 미완료 영역

2. **공통 대응/체인**: 주문/소환/파괴/묘지/대상 이동 등 이벤트 → 양측 우선권·응답/포기 → 비용/선택 확정 → LIFO → 후속 자동 트리거까지 원자적 처리.
3. **상태 시스템 통합**: 원래 소유자와 현재 조종자, 장착/일체화/얼라이즈 소재 동반 이동, 일시/영구 수치, 실제/취급 공격력, 복사 시 독립 히스토리.
4. **AI**: 합법 행동 열거/실행 가능성, 특수 효과 선택, 고난도 전략, 상대 비공개 정보 사용 금지, 무한 행동 방지의 올바른 처리.
5. **재정/구현 분리**: docs/RULINGS_CONFIRMED_2026-10-13.md는 17개 새 공식 재정, docs/OPEN_RULINGS_REGISTER.md는 잔여 13개 구현·검증 항목. 확정 규칙과 미완료 코드를 혼동하지 말 것. 미확정 추측을 정식 재정으로 바꾸지 말 것.
6. **검증**: 모든 카드 효과·24×24 덱 조합·동일 덱 대전·상태 기반 랜덤 검사·고정 난수 재현·보안 부하 테스트.

## 5. 실행 명령 (저장소 최상위에서)

~~~bash
npm start
npm test
npm run check:data
npm run test:matrix
npm run check:coverage
~~~

- npm start 후 http://localhost:3000 접속.
- npm run check:coverage 는 자동 보고서 3개를 재생성한다. **수동 해설 AUTOMATION_NOTES.md는 보존**한다. CI와 동일한 읽기 전용 검사는 npm run check:coverage -- --check. 효과 명세는 docs/effect-coverage.json을 수정한 뒤 재생성할 것.
- npm run test:matrix 는 24개 덱을 AI에 배정하는 진행 스모크 검사이며 **카드 전 효과 정답성 테스트가 아니다**.
- 서버는 기본 .data/rooms.json에 방 상태를 저장. 실제 운영용 DB 아님.
- CI: .github/workflows/ci.yml / test.yml.

## 6. 절대 바꾸면 안 되는 개발 원칙

- 다른 덱 카드를 사전 혼합하거나 삭제된 8개 덱을 재추가하지 않는다.
- 카드의 수치·조건·비용·효과 의도를 임의로 조정/생략/밸런스 패치하지 않는다.
- 원문과 충돌하면 사용자 확정 재정을 우선한다. **간드레이드래곤은 자기 자신을 제외한 나머지 몬스터를 파괴**한다.
- 구현하지 않은 효과를 완료라 표시하지 않는다. 실패 시 조용히 효과를 소모하거나 가짜 기본 효과를 실행하지 않는다.
- AI와 사람은 반드시 동일한 서버 검증 규칙을 사용한다. 공격/다이스/셔플/손패 공개·효과 판정은 서버 권위.
- 사이트가 자동 판정할 수 없는 고유 효과는 명확히 표시하고 공식 룰북의 미확정 부분을 임의 확정하지 않는다.
- 중요한 카드 ID와 자연어 원문 및 이전 v1.2 문구를 추후 검증 가능하도록 보존한다.
- 자동화가 가능해도 **사용자에게 승인받지 않은 미확정 재정은 확정 규칙이 아니다**.
