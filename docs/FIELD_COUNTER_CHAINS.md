# 필드 무효화 3종과 다중 대응 — 2026-10-14

관련 #22/#23/#24/#25/#26/#27. 기존 61종 주문·21종 엑스트라 소환 창을 재사용한다. COC-12-002의 플레이 카탈로그 문구는 최신 사용자 정정에 따라 수정했다. 부재한 v1.3 정본 자료를 새로 만든 것은 아니다.

## 2026-10-14 사용자 정정 — 라이징 윈드 걸은 몬스터 효과만

사용자: **“라이징 윈드 걸의 효과는 몬스터의 효과만 무시야. 그걸 반영해서 다시 정리하고 텍스트도 바꿔줘”**.

COC-12-002의 플레이 카탈로그 문구를 “1회 상대 효과를 무효로 합니다.”에서 **“1회 상대 몬스터의 효과를 무효로 합니다.”**로 정정한다. 상대 주문·일체화 스톰블레이거의 효과·소환 자체는 대상이 아니다. **재소환 시 재사용 가능**은 유지한다. PR #68의 더 넓은 대응 범위는 이 정정으로 대체하며 다시 묻지 않는다. 현재 구현은 등록된 몬스터 카운터3종 및 필드 발동5종의 효과 대응이며, 모든 몬스터 발동·유발을 완성한 것은 아니다. [구현 명세](FIELD_COUNTER_CHAINS.md).

## 사용자 확정과 카드별 명세

사용자는 세 카드의 “1회” 초기화 시점을 **“다시 소환되면 재사용 가능”**으로 확정했다. 현재 필드 체류 중 사용 후 다시 소환되면 재사용할 수 있다. 단순 필드 간 조종권 이동이나 재접속으로는 초기화하지 않는다. 스톰블레이거의 기존 게임당1회는 변경하지 않는다.

| 카드 | 합법 소스 | 대응 대상 | 사용 제한 |
|---|---|---|---|
| COC-12-001 블래스트 보이 | 자기 필드 | 마지막 상대 주문 | 필드 체류 중 1회, 재소환 시 초기화 |
| COC-12-002 라이징 윈드 걸 | 자기 필드 | 마지막 상대 몬스터 효과 (현재 몬스터 카운터3종·필드 발동5종) | 필드 체류 중 1회, 재소환 시 초기화 |
| COC-24-005 디텍티브 매치 | 자기 필드 | 마지막 상대 주문 | 필드 체류 중 1회, 재소환 시 초기화 |
| COC-14-001 스톰블레이거 | 자기 일체화 | 마지막 상대 주문 또는 엑스트라 소환 | 같은 실제 카드의 주문/소환 합계 게임당 1회 |

세 필드 카드의 소환 조건은 기존 발동 사전검사를 따른다. 무효화 선언 자체에 원문에 없는 HP/패 비용을 추가하지 않는다. 선언 시 사용 횟수를 소비하며 카운터가 무효화되거나 소스가 사라져도 현재 필드 체류의 사용을 돌려주지 않는다.

## 공통 대응과 해결

`src/counter-effects.mjs`가 마지막 상대 스택 항목의 종류·소유자, 현재 대응권자, 소스 영역/조종자·무효 상태·사용 기록을 검사한다. 주문 전용 무효화로 몬스터 효과나 원래 소환을 무효화할 수 없다. 라이징 윈드 걸도 **소환 자체는 효과가 아니므로 직접 소환 무효화를 하지 않는다**. **상대 주문과 스톰블레이거의 일체화 효과도 대상이 아니다.** 몬스터 효과 여부는 선언에 저장한 카드 ID와 등록된 소스 종류로 판단하며, 모든 무효화 효과를 몬스터 효과로 취급하지 않는다.

예: 회복 주문 → 상대 블래스트 보이 → 자기 라이징 윈드 걸 → pass. 후발 윈드 걸이 블래스트 보이 효과를 무효화하므로 회복 주문은 해결한다. 상대 윈드 걸이 한 번 더 대응하면 그 효과가 먼저 해결되어 최초 회복 주문은 무효화된다. 지불한 주문/소재 비용과 이미 선언한 각 카드의 사용 횟수는 유지한다.

카드 ID·현재 조종자·선언 시 영역 세대를 기록한다. 일반 소스가 필드를 떠났다가 같은 UID로 돌아와도 **이전 선언은 불발**한다. 재소환된 새 체류의 사용 가능 상태는 별도다. 필드 간 조종권 변경 역시 이전 선언의 소스 상태가 바뀐 것으로 검사한다. 스톰블레이거의 옛 저장 항목은 추가 필드가 없어도 기존 형식으로 해결한다. PR #68에서 저장된 윈드 걸의 주문/일체화 대상 선언은 최신 규칙에 따라 불발 처리하고 이미 쓴 횟수를 유지한다. 원래 주문/소환 및 스톰블레이거 효과는 정상 해결하여 대전이 막히지 않는다.

대응 창은 기존 행동을 막고 현재 대응권자만 다음 카운터 또는 pass를 선택한다. 클라이언트가 임의 스택 항목을 지정할 수 없으며 서버가 마지막 상대 항목으로 고정한다. 처리 실패는 기존 HTTP 트랜잭션으로 비용/횟수/버전/파일을 복구한다.
