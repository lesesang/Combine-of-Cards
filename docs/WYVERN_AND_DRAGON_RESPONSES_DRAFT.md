## 와이번11-004: 영역을 바꾸는 발동

`zone-abilities.mjs`에 자기 MAIN, 본인의 패/덱 또는 현재 조종하는 필드의 와이번, 효과 유효/사용 가능 상태, 실물UID의1번 효과 미사용을 확인하는 공통 계획 함수를 추가했다. 다른 영역 하나를 선택하며 현재 영역 재선택·묘지/제외 출발은 거부한다. 비용은 없고 필드 목적이면 선언 시 빈 칸이 필요하다.

발동 시 선택한 와이번을 공개하고 UID·현재 영역·보유자/조종자·체류 번호·목적지를 저장한다. 실물별 사용 횟수는 즉시 소모하며 영역 이동이나 무효화로 되돌리지 않는다. 같은 이름의 다른 실제 카드는 독립이다. 자기 MAIN 제한은 일반 발동 원칙을 적용한 개발자 명확화이며 상대 턴 예외를 새로 만들지 않는다.

윈드 걸이 대응할 수 있는 몬스터 효과로 선언한다. 해결 때 원본의 영역/체류/조종자/현재 무효를 다시 확인한다. 패/덱 목적은 원래 소유자에게 보내며 덱은R11대로 그 카드만 임의 인덱스에 삽입한다. 필드 목적은 기존 효과 소환 대기열에 넣고 **별도 소환 선언·스톰 대응**을 거친다. 무효화되면 출발 패/덱을 유지한다. 빈 자리/원본 체류/사용 금지/카드 정체성도 소환 해결 때 확인한다.

PvP에는 서버가 만든 이동 선택 목록과 각 와이번의 현재ATK/HP를 표시한다. 목록은 요청한 플레이어에게만 제공하며 상대 덱이나 덱 순서를 노출하지 않는다. AI3난이도도 같은 목록으로 덱/패에서 전개한다. 중/상은HP50미만의 와이번을 패로 회수하는 간단한 보존 선택을 추가했다. 이 선택 정책은 승률/전술 품질을 검증한 결과가 아니다. 건강한 카드를 반복 이동시키는 기본 행동은 넣지 않았다.

와이번은 새로운 영역 발동 경로 **1종**으로 집계한다. 기존 필드25에 중복 합산하지 않는다. UI의 일반 패 소환과 이 효과 소환은 별개이며, 이 효과의 실물별 횟수가 일반 소환 횟수로 바뀌지는 않는다.

## 파프니르11-007: 일반/효과 소환 성공의 생성 유발

기존 공통 `H.onSummon`을 거친 일반·부활/효과 소환 성공에 황금/반지 생성 유발을 추가했다. 소환 자체가 무효화되면 생성하지 않는다. 소환 유발은 현재 소스 체류·조종권·효과 무효와 실물별 효과1 제한을 확인하고 윈드 걸 대응 후 생성한다. 무효화되면 그 생성은 하지 않는다.

`createDragonTreasures`는 카탈로그에 이미 있는 황금/반지를 각각 새 실물로 만들고 실제 파프니르UID 및 두 카드의 연결을 저장한다. 없는 원본 카드를 만들어 넣는 기능이 아니다. 토큰에 반응하는 기존 파프니르 즉시 소환도 생성 함수를 공유하도록 정리했다.

**토큰 자동 소환 경로까지 대응을 완성한 것은 아니다.** 현재 그 경로는 직접 필드 이동→황금/반지 생성→보물 전환으로 남는다. 토큰 여러 장 생성 사이의 필드 공간·파프니르 선행 소환·황금 사용 대응을 함께 다루는 재개 가능한 처리와 슬롯 예약이 필요하다. 일반 경로만 바꾼 뒤R07의 우선 순서가 완성됐다고 표시하지 않는다. 황금의 패 진입 즉시 사용도 아직 별도 주문 대응으로 옮기지 않았다.

## 황금11-008: 어택 시작의 공통 순서·주문 효과 대응

어택 시작에 활성 황금 인스턴스마다 보물5개 유발을 선언한다. 이제 용왕50·오로치 누적 피해와 **같은 자동 유발 그룹**에 들어가므로 같은 우선도 선언 순서를 선택하고 역순 해결한다. 독립 지속 상태의ID·소유자·사건 턴을 저장하고, 해결 시 해당 상태가 유효하고 자기ATTACK인지 확인한다. 어택 생략/MAIN 효과 공격은 발동하지 않는다.

발동 소스 분류를 주문 효과로 추가했다. 스톰·블래스트·디텍티브의 주문 무효 범위에 들어가고 윈드 걸의 몬스터 전용 무효에는 들어가지 않는다. 무효화되면 이번5개만 추가하지 않으며 황금 지속 상태를 제거하지 않는다. 물리적 황금 카드가 묘지에서 다른 영역으로 이동해도 이미 등록된 독립 효과는 유지한다.

마검의 강제 지불은 기존 우선 경로에 남는다. 황금·용왕·오로치의 그룹 통합이 모든 어택 시작 사건의 전역 통합을 의미하지 않는다. 파프니르 새 보물 증가분의 강화와 과거 미적용 보물/무효 이력은 이전 구현 범위 그대로다.

## 반지11-009: 파괴 이력 보관·대응·황금 종료

이전 `onFafnirDestroyed`는 파괴 처리 도중 별도 실행기로 **현재 효과 스택 전체를 비우는 호출**을 했다. 이제 그 함수는 연결된 황금을 종료 대기로 표시하고, 보물 수·반지UID/묘지 체류·황금 인스턴스ID·생성 소유자를 보관해 공통 지연 유발에 넣는다. 부모 주문·비용/파괴 처리의 스택을 직접 실행하지 않는다.

자동 사용은 연결된 반지가 황금 소유자의 패에 있고 주문 사용 금지가 아닐 때만 가능하다. 사용한 반지를 공개해 묘지로 보내고 카드 사용 이력을 기록한 뒤 대응한다. 사용할 반지가 없으면 강화 없이 황금을 종료한다. 파프니르의 조종권이 바뀌어도 연결은 같은 실제 파프니르를 가리키며, 보상은 황금 소유자의 플레이어에게 간다. 기존 코드는 조종자 일치에만 의존해 종료를 놓칠 수 있었다.

- 반지는 보관한 보물 수×10을 공통 강화 함수에 전달한다. R08대로 플레이어HP/공격력 보너스를 저장해 현재/이후 일체화에 한 번 적용한다. 용왕/꽝철이 배율은 해결 당시 받는 플레이어 기준이다.
- 원본이 같은 묘지 체류에 남았을 때 강화하고 반지를 제외한다. 원본 이탈/재진입이면 강화는 불발한다. 주문 효과 무효화라면 강화하지 않고 이미 사용한 반지는 묘지에 남는다.
- 해결·무효·소스 불발 어느 결과에서도 공통 정리 단계가 황금을 종료하고 황금 카드를 제외한다. **반지 처리→황금 종료** 순서는 유지한다. 반지 원본이 없어져도 정리할 선언을 버리지 않는다.
- 종료 대기 중인 황금은 새 토큰/어택 보물을 받지 않는다. 다른 파프니르/황금과 종료 대기 인스턴스를 혼동하지 않는다. 여러 파괴 보상은 기존 동시 유발 순서 선택을 사용한다.
- 같은 피해/파괴 처리에서 발생한 반지 회복이 끝나기 전 일반HP 승패 확정을 잠시 보류한다. 단 **마검 플레이어의30HP 지불 불가 즉시 패배**는 확정 강제 패배로 별도 기록해 대기 중인 반지가 되살리지 못하게 했다. 지불액/기본 강화/다음 자기 턴×2 재정을 바꾼 것이 아니다.

사용/보관/종료 상태는 JSON 객체·숫자·UID로만 저장한다. 공통 대응 UI·AI·재접속 저장 경로를 사용하며, 실제 D1 저장·원자성 검증은 아직 하지 않았다. 새 이동 경로도 공통 효과 소환 큐를 사용한다.
