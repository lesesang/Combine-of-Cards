# v1.3 카드·룰북 원본 출처 및 GitHub 정본 편입 작업

**목적:** 새 채팅에서 카드 텍스트가 없는 상태로 구현하거나, 간략한 사이트 도감을 전체 원본 문서로 오인하는 것을 방지한다.

## 1. 자료의 생성 경위

이전 ChatGPT 대화에서 사용자가 직접 제공한 **32개 MHTML 덱 자료**(15개 + 17개)를 추출·대조했고, 삭제 확정된 8개 덱을 제외한 **24개 덱·254개 카드 레코드**를 정리했다. 2026-10-12에 지금까지의 규칙 수정 및 표기 통일을 반영해 **v1.3 룰북/카드 데이터**를 별도로 생성했다.

## 2. 현재 GitHub에 있는 데이터

- **public/data/catalog.json.gz.b64** — 24덱 254카드의 플레이용 도감 JSON을 gzip 압축·base64 변환한 것. 서버는 실행 시 이 파일을 우선 읽는다.
- **scripts/build-data.mjs** — v1.3 정본 JSON을 받아 플레이용 도감으로 변환하는 변환기. 입력 기본 경로 public/data/source-cards.v1.3.json은 **현재 저장소에 없음**.
- **scripts/verify-data.mjs** — 최소한 덱 수/장수/삭제 덱·카드 수 등의 구조 검증.
- **docs/AUTOMATION_COVERAGE.md** — 실행 코드가 인식하는 카드별 지원 상태. 카드 원문 자료가 아니라 부분 구현 현황이다.

**중요:** build-data.mjs만 실행하면 public/data/catalog.json이 만들어진다. 현재 server.mjs은 **catalog.json.gz.b64가 존재할 경우 그것을 먼저 읽으므로**, 정본 JSON이 추가되어 데이터를 다시 빌드할 때는 압축 파일도 **함께 갱신**해야 한다. 단순히 catalog.json만 고치면 서버가 오래된 압축 도감을 계속 쓸 수 있다.

## 3. 정본 편입 전에 꼭 할 일

1. 기존 채팅에서 **v1.3 DOCX/Markdown/JSON 산출물의 정확한 바이트**를 확보한다. 이전 v1.2나 27덱 자료로 대체하지 않는다.
2. 보유한 원본과 생성 카드 데이터를 대조하고, 24덱/254장·고유 ID·속성·효과 수·대상·비용·수치를 기계 검사한다.
3. 공개 GitHub 저장소에 카드 원문/원본 MHTML/아트워크를 추가해도 되는지 제작자/동호회 권리 범위를 확인한다. 정본 텍스트만으로 충분하면 개인 원본 MHTML의 불필요한 메타데이터/개인정보는 커밋하지 않는다.
4. 공개 가능 범위에서 versioned source/v1.3/ 또는 data/source/v1.3/ 등에 텍스트·JSON 정본, 변경 로그, 기계 검증 스크립트를 편입한다.
5. build-data.mjs 결과와 **압축된 실제 서버 도감**을 함께 재생성해 JSON 필드·카드 효과 문자열이 일치하는지 검사한다.
6. 모든 카드 효과마다 원문 ID/순서, 조건/비용/트리거/대상/해결/지속/종료 사건을 대응시키고 기존 v1.2 대비 변경 로그도 보존한다.
7. 카드/엔진 버전을 바꾸면 **진행 중 게임 상태가 갑자기 새 규칙으로 바뀌지 않도록** 매치 버전 고정·마이그레이션 방침을 마련한다.

## 4. 원본과 코드가 불일치할 때

- 이미 사용자가 **확정한 재정**(특히 간드레이드래곤 자기 자신 제외, 황금/반지 선후 해결, 어그로, 리로드 등)은 구버전 문구보다 우선한다.
- 확정이 아니라 임시 코드 해석인 경우는 docs/OPEN_RULINGS_REGISTER.md에 올리고 **사용자 승인 전 정본 수정이라고 표시하지 않는다**.
- 텍스트 통일은 문체·용어의 표준화일 뿐 **수치·비용·효과·발동 조건의 임의 변경은 금지**.
- '블랙 메탈 퓨전 업 공격 기회 사용 비용'처럼 원문 대비 카드 효과 일부가 빠져 나갈 수 있어 **원문 대조 필드**를 보존한다.
