# 효과 스택 및 독립 지속 효과 (v1.3 / 개발 중)

## 적용한 공통 엔진

`src/effect-runtime.mjs`은 게임방 JSON에 저장 가능한 데이터만을 사용한다. 발동을 선언하면 `effectStack`에 추가되고, **나중에 발동한 효과부터 해결**한다.

- 일반 필드 발동: 해결 시 해당 카드가 필드나 일체화 영역을 떠났다면 무효화
- 예외: 파괴 시 발동, 묘지 발동, 발동자가 자신을 비용으로 보낸 경우, 독립적으로 등록된 지속 효과
- 동일 사건에서 자동 발동이 여럿이면 확정된 명시적 우선순위를 먼저 적용하고, 같은 우선도에서는 현재 턴 플레이어 효과를 먼저 선언한 다음 상대 효과를 선언
- `registerPersistent`는 발동한 카드가 묘지로 이동해도 별도 레코드로 카운터·앵커·종료 조건을 유지
- 해결 256단계 및 동시에 열린 효과 256개 상한은 **서버 보호용** 제한이며 새로운 카드 사용 횟수 규칙이 아님. **R26 PR #41**: 효과 스택의 `fingerprint(room)`를 제공하면 **동일한 실게임 상태 + 동일한 선언된 스택**이 다시 등장하는 순환만 중단하고 진단 코드 `EFFECT_CYCLE`을 내며, HP/카운터 등 게임 상태가 변하는 유한 반복은 합법적으로 유지. 256단계 초과는 `EFFECT_SAFETY_LIMIT` 진단으로 구별하고 **자동 패배/승리를 선언하지 않음**. 전체 게임 이벤트/AI 순환의 완전 검출은 미구현

**2026-10-13 R01/R02 부분 연결:** `beginAutomaticTriggerOrder`는 같은 사건에서 동일 우선도의 자동 효과가 한 플레이어에게 여러 개 발동할 경우 `pendingTriggerOrder`에 선택권/효과 키/카운터를 JSON으로 보존합니다. 현재 턴 플레이어가 먼저 자기 효과들의 선언 순서를 정하고 상대가 다음에 정하며, 서버는 권한·효과 중복 선택을 검사합니다. 현재는 **동시 파괴 및 개별 필드 파괴 시 `firstDestroyHeal`** 효과를 이 경로로 연결했습니다. 개별 파괴에서도 복수 자동 효과면 대기, 한 효과면 스택으로 즉시 해결합니다. **손패 카드 파괴는 필드 파괴 유발 사건으로 취급하지 않습니다(R24).** 선언 후 역순 해결, 회복 전에 파괴 직전 HP 스냅샷 유지, AI 순서 선택, 대전 UI 재접속을 테스트합니다. 일반 단일 파괴·다른 카드 효과는 아직 혼재합니다.\n\n**2026-10-13 PR #42 — 주문 체인 첫 실제 연결:** 카드 `COC-07-003` (상대 드로우·덱 3장 묘지), `COC-13-007` (상대 HP 10% 흡수), `COC-17-003` (자신의 체력 및 필드 몬스터 회복)은 발동 시 주문 카드를 묘지로 보내 비용을 지불하고 `pendingSpell` 응답 창에 별도 효과를 등록한다. 상대 플레이어가 `spellResponse(pass)`하면 **선언 스택에서 주문 효과가 해결**된다. 서버/UI/AI가 같은 응답 경로를 사용하고 재접속·승패·비공개 상태를 검증한다. 해당 세 카드 외에는 이전 자동/수동 판정 경로를 보존하므로 **일반 주문 전체의 대응/무효화 자동화는 아직 아니다.** 실제 주문 무효화 카드 대응은 아직 연결되지 않아 임의 무효화 API 요청을 거부한다.

**PR #44 추가:** 위 세 주문에 더해 `COC-07-010`, `COC-08-007`, `COC-10-009`, `COC-19-004`, `COC-20-005`, `COC-30-005`, `COC-30-007` 7종을 같은 응답 스택에 연결했다. 카드 발동과 실제 효과 해결을 구분하며 1회성 회복 유발·양측 공유 주사위·조건 없는 덱 검색/지속 보너스도 응답 이후 처리한다. 사용자 선택과 사전검사가 필요한 다른 주문은 무리하게 이 경로로 옮기지 않는다.

**PR #47:** 별도 표적 선택이나 추가 발동 비용이 없는 주문 COC-07-004, COC-07-011, COC-17-004, COC-31-005를 같은 대응 체인에 추가했다. 토큰 생성·패 비공개 난수/동전 판정·대상 없는 덱 검색도 선언 이후 상대 pass 시 해결한다. 전체 카드 체인 완료는 아니다.

**주의:** 현재 일반 주문의 발동·대응을 모두 해당 스택으로 대체하지는 않았다. 아직 모든 카드에 대한 연쇄 선택권, 선언 시점, 대응 창, 원인별 무효화 검증은 남아 있다. 이 코드는 완전 자동 체인의 전단계다.

## 용·드래곤 덱의 실제 연동

- `COC-11-007` 탐욕의 악룡 파프니르: 덱 또는 패에 존재할 때 토큰이 생성되면 소환 가능한 빈 칸에 자동으로 소환
- `COC-11-008` 라인의 황금: 파프니르 소환 후 패에 생성되며 즉시 자동 발동. 카드 자체는 묘지로 가지만, 보물 수는 서버 `persistentEffects`에 보존. 새 토큰을 보물로 전환하면 카운터 +1 및 파프니르 공격력·체력 +10. 자신의 공격 페이즈 시작 시 카운터 +5 및 공격력·체력 +50
- `COC-11-009` 니벨룽겐의 반지: 파프니르 파괴 시, 황금 종료 전에 기록된 보물 수를 가져와 수 × 10만큼 플레이어 체력과 공격력 상승. 반지는 게임에서 제외되고 황금도 삭제. 플레이어 공격력 보너스는 이후 일체화에 적용
- 파프니르는 이 시스템에서 토큰 사용/생성에 의한 자동 소환만 가능하며 손패 일반 소환은 거부

## 확정된 규칙과 아직 남은 구현

1. **R05 확정:** 토큰의 생성·소환·사용·릴리스 **전부 포함**. 현재 생성/소환 배치 및 일부 토큰 릴리스만 공통 훅에 연결. 남은 토큰 이벤트 경로도 통합해야 한다.
2. **R06 확정:** 한 토큰 사건은 한쪽 황금에만 적립. **토큰 조종자 측 황금 우선**, 없으면 상대 측 유효 황금. 구현·테스트 갱신.
3. **R07 확정:** 성공적인 토큰 생성/소환, 파프니르 선행 소환, 황금 전환 순서. 전환은 파괴가 아니라 별도 소멸/영역 이동.
4. 현재 파프니르의 빈 필드 슬롯 판정은 토큰이 놓인 직후 소환 전 검사한다. 공통 소환 대응/슬롯 예약은 별도 엔진 작업으로 추적한다.
5. **R08 확정:** 반지 강화는 플레이어 고유 공격력 보너스에 귀속되고 일체화 중/이후 한 번 적용한다. 플레이어 자체 공격 시스템의 완전한 독립 모델은 추가 구현이 필요하다.

확정되지 않은 분기까지 임의로 '완전 자동화'로 선언하지 않는다.

## R01/R02 등록 실패·JSON 저장 사전검사 (2026-10-13 후속)

- 단일/그룹 선언과 독립 지속 효과는 저장할 데이터를 먼저 복사·검증한 뒤 상태를 변경한다. JSON에 보존되지 않는 Map/Set/Date, BigInt, 순환 참조, 비유한 수치는 거부한다. HTTP와 AI의 선택적 객체 필드 `undefined`는 등록 시 생략하여 저장 전후 의미를 맞추며, 배열의 누락 값은 거부한다.
- 자동 효과 순서 선택 창을 열기 전에 모든 선언의 소스 ID·예외·페이로드와 전체 시퀀스 여유를 검증한다. 사전검사는 실제 선언 번호나 기본 순서를 확정하지 않는다. 기존 현재 턴 플레이어 우선 선택 및 LIFO 해결을 유지한다.
- 지속 효과 등록 실패는 배열 생성이나 시퀀스 소비를 남기지 않는다. 안전한 정수 범위를 넘는 지속 효과 ID 생성도 거부하며 기존 동일 소스/종류의 중복 등록 동작은 유지한다.
- `tests/effect-registration.test.mjs` 및 `tests/effect-registration-api.test.mjs`: 잘못된 입력 후 재시도, 순서 선택·지속 효과의 JSON 복원, HTTP 요청 실패의 카드 비용·버전·디스크 롤백, 재시작 후 주문 pass 및 중복 요청 거부.
- **범위 제한:** 등록 경계의 사전검사이며 모든 게임 상태의 스키마 검증·실제 카운터 카드·범용 전역 체인 완성은 아니다. 새 카드 지원 상태나 효과 번호를 추가하지 않는다.
