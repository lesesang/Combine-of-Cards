## 공통 소환/선택과 실제 이력

`effect-summon-batches.mjs`는 후보 UID·현재 영역·선택 순서를 JSON으로 저장한다. 자신만 패/덱 후보를 보며 덱 순서를 노출하지 않는다. 상대에게는 실제 선언한 카드만 공개한다. 후보/빈 필드/허용 수량 중 최소 수량을 선택하고, 선택한 순서로 소환 선언 → 상대 스톰블레이거 대응 → 소환 → 그 카드의 소환 유발/선택 완료 → 다음 소환을 진행한다. UI는 목록 순서, API는 제출 순서다. 자리가 사라지면 남은 소환은 중단하며 선택 카드가 영역을 옮기거나 사용 금지되면 건너뛴다. 카드나 복제본을 임의 생성하지 않는다.

일반 패 몬스터도 같은 소환 대응을 사용한다. 원래 소환 조건과 비용은 선언 전에 검사/지불하고, 무효되면 패에 유지하며 비용을 반환하지 않는다. 성공할 때만 필드 진입/사용 이력/소환 유발을 기록한다. 비용으로 발생한 첫 파괴 회복의 순서 선택이 남으면 `cost-triggers` 단계로 소환 선언을 보관하고 회복 해결 후 대응을 연다. 일반 소환은 여전히 자기 MAIN에서만 가능하다.

새 사용 이력은 `usedCardsGame`, 실제 파괴/이탈은 `wasFieldDestroyed`/`hasLeftField`로 보관한다. 단순 버리기를 파괴로 세지 않고, 묘지를 보고 과거 소환/파괴를 추측하지 않는다. 구 저장에서 이력이 없으면 이후 실제 사건부터 기록한다. 이 때문에 구 대전에서 이미 이뤘던 조건/사용 장수가 완전히 복원되지는 않는다. `historyAttackBonus`는 기본ATK/기존 강화와 분리해 진화의 새 기본값 교체, 무효 중 억제, 마검 독립 배율을 유지한다. 야시키 역시 현재 소스/필드를 검사하는 별도 지속 층이다.

`pendingTriggerTargetChoice`와 `pendingSummonBatch`는 사람/AI 공통 행동 검사, 선택 중 다른 행동/열람 잠금, 승패/항복 정리, 저장 복구를 위한 JSON 상태로 연결했다. AI는 공개 필드 또는 자신의 합법 후보만 평가한다. 사전검사에 통과한 등록 몬스터는 복잡한 조건 문장이 있다는 이유로 후보에서 제외하지 않도록 연결했다. 중/상은 현재 사용 가능한 수치 기반 선택을 하며 난이도 성능을 검증했다는 뜻은 아니다.

## 위임에 따른 개발자 해석 — 사용자 신규 확정과 구분

- ‘사용한 카드 하나당’은 같은 물리 UID를 회수해 재사용해도1장으로 센다. 서로 다른 실제 복제본은 각각 센다. 인피니티/지니어스는 진화 전 이력과 진화 후 성공 소환을 계속 반영한다. 이는 작은 덱의 회수 루프로 무한 공격력이 커지는 것을 막으면서 여러 기체/매치를 활용하는 덱 흐름을 보존하는 해석이다.
- 백귀야행·드라고닉은 명시된 자동 진입 시점이 없어 기본 자기 MAIN의 UID/효과별 턴1회 발동으로 구현했다. 진화만으로 자동 발동하지 않는다. 백귀야행/메디컬의 부활은 정상 소환 조건을 다시 요구하지 않되 실제 묘지의 파괴 기록이 필요하다. 버닝소울/최후의 희망의 불명확한 후보 영역은 자신의 패·덱·묘지로 한정하고 제외/엑스트라를 임의 복구하지 않는다.
- 여러 장 효과 소환은 위의 순차 선언 정책을 사용한다. 모든 몬스터를 동시에 놓는 소환이나 한번의 무효화로 전체 묶음을 취소하는 구현이 아니다. 한 소환이 무효되면 그 카드만 원래 영역에 남고 이미 낸 비용은 돌려주지 않는다. 기존 사용자 확정인 엑스트라/원소 교체의 원래 영역 유지와 일관되게 확장한 개발자 정책이다.
- 버닝소울의 절반 지불 후 HP는 소수점 버림이며 HP1에서 생존 비용을 지불할 수 없다. 어나더의 사용 금지는 효과 해결 때 적용하고 이후 어나더가 필드를 떠나도 남는다. 효과 자체가 무효되면 강화/사용 금지는 적용하지 않는다. 다른 라이드머신 금지와 단순 소환 조건을 분리한다.
- 소환 유발은 UID/효과별 같은 턴1회로 제한하고, 소환 사건의 시점이 명시되어 있어 상대 턴의 실제 소환도 처리한다. 반환/탈취/제외 대상은 대응을 마친 효과 해결 단계에서 고른다. 일반 유발은 소스 이탈/재진입·조종권 변경·무효로 불발한다.
- COC-26-004의 파괴 유발은 승인된 자기 파괴 예외를 사용한다. 원인 몬스터는 같은 체류에 남아야 피해를 받으며, 일체화/주문 발동자 귀속은 해당 플레이어에게 피해를 준다. 원인을 모르는 파괴는 임의로 상대에게 귀속하지 않는다. 마검 처치 보너스를 엉뚱한 플레이어에게 주지 않도록 죽은 매치를 피해 소스로 남긴다.
- 야시키는 현재 자기 요괴에 적용되는 지속 강화로 해석해 반복 버튼으로 영구 +100을 누적하지 않는다. 진화/이탈/소스 무효 시 지속 층만 제거한다. 악귀환월빙의흉담의 조건 칸은 선언 시 지연 파괴 약정으로 선지불하며, 주문이 무효되어도 약정은 유지한다. 대상의 같은 필드 체류만 추적하고 현재 효과 파괴 면역은 해결 시 적용한다.

기존17공식 재정·마검 지불/기간/배율 중첩·장착 임의 해제 금지·간드레이 자기 제외·진화/복원·개별 물리 카드 횟수·원소1번 공유 예외를 변경하지 않았다. 카탈로그 원문/수치를 덮어쓰거나 부재한 정본을 만들지 않았다.

## 남은 범위와 후속 검증

- 일반 패 몬스터와 이 네 묶음 외의 모든 자동 토큰/복제/특수 카드 소환을 아직 공통 대응으로 옮기지 않았다. 기존 단발 소환 유발 전체와 지속·파괴·턴 시작 사건의 완전한 동시 우선순위도 미완료다.
- 베리아/스트로베리아 묘지 이동 발동 감지, 케미 회수, 원죄/아젤리아/유리카/하우스 파티 복사, 장착 수명, 데스 라이터의 다이스 선택 등은 다음 구현 대상이다. ‘베스트 지니어스’를 요구하는 기존 소환 조건을 진화 이름에 임의로 확장하지 않았으며 이름 취급은 별도 덱 검토가 필요하다.
- 현재 draft 등록은 **주문 핸들러76·대응68·필드22·공통 몬스터 유발12**이다. 이 숫자는 실행/완성도 증명이 아니다. 생성 보고서와 효과 증거는 main PR #74의 기준선으로 보존했으므로 후속 일괄 검증 때 새 레지스트리와 함께 재생성/정합성 검사를 해야 한다.
- 기존 테스트 중 즉시 패 소환, 즉시 카사/네코 효과, 플레임/볼케이노 추가 공격을 기대하는 경로는 새 대응과 선택을 거쳐 결과를 확인하도록 갱신해야 한다. 테스트/CI를 삭제하거나 약화하지 않았다.
- 후속 일괄 검증: 정상/무효/비용 미환불·개별 UID/재소환·역순 카운터·다중 소환 중 유발/중단·원인 귀속·지연 파괴/회복·승패·진화/무효/마검·저장 재시작·선택 권한/비공개/동일 요청/버전 충돌·PvP UI·AI3난이도, 이후 Node tests와 Verify TCG beta. 현재 이 검증을 실행하지 않았다.
- 개인 Cloudflare D1은 여전히 계획 단계다. 새 상태도 JSON 자료만 사용했지만 실제 D1 어댑터·CAS·이전·배포는 미완료다. 전254장 자동화와576상성 검증을 완료했다고 표시하지 않는다.
