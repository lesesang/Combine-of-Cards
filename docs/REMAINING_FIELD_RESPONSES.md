## 재정 해석과 남은 범위

쿠로쿠로비의 반환을 발동 비용으로, 라이드 머신 플레임의1회를 실물 게임1회로 처리하는 기존 엔진 정책을 유지한다. 프람덴베르카는 자신의 몬스터 파괴를 발동 비용으로 명시한 원문에 따라 선지불한다. 파괴 면역 아군은 제물 불가, 실제 파괴 뒤 부활한 아군은 이미 지불한 제물이다. 사용 횟수는 이탈/조종권 변경/저장 복원으로 초기화되지 않고 다른 실물 카드는 독립적이다. 이 해석들을 새 사용자 개별 확정으로 기록하지 않는다.

슈의 소환 무효 시 원래 영역 유지와 해결 뒤 선택은 이미 확정된 원소 교체의 처리와 일관되게 적용한 **개발자 결정**이다. 원소 교체에 관한 사용자 답변 자체가 슈까지 명시했다고 주장하지 않는다. 슈가 효과 해결 전에 떠나면 불발하지만, 효과가 해결되어 선택이 시작된 뒤에는 소스 재검사로 이미 생긴 소환을 취소하지 않는다.

이 PR은 슈/프람덴베르카 일체화 자체의 소환 조건(상대 빈 필드3턴 이력, 세 배회자 사망 이력)까지 완성하지 않는다. 전체 소환/파괴/묘지 반응, 복제 효과, 일반 대응 중 임의 효과 삽입, 다른 카드의 조건 무시 소환은 미완료다. 윈드 걸은 몬스터4종에만 대응하고 두 일체화에는 대응하지 않는다. 스톰블레이거는 슈의 일체화 효과가 아니라 뒤따르는 실제 소환에만 대응한다.

## 서버·PvP·AI·영속 상태

- 모든17종은 `prepareFieldEffect → payFieldEffect → resolveFieldEffect` 검사를 공유한다. 더 이상 나머지6종만 쓰는 별도 즉시 실행 서버 경로가 없다. 테스트용 직접 실행 헬퍼는 남는다.
- 소스/대상 UID·조종자·영역 세대를 확인한다. 파괴 비용의 후속 사건은 `cost-triggers` 대기 단계를 이용하며, 원소 자기 비용 예외를 일반 일체화에 잘못 적용하지 않는다.
- 슈의 `pendingRecruitChoice`에는 선택권자만 저장한다. `recruitChoice` 행동으로 후보를 다시 검사하고 `pendingExtraSummon(method=recruit, originZone)`을 만든다. 후보 ID는 정렬하여 덱 순서를 노출하지 않고 선택권자에게만 공개한다. 선택 뒤 소환 대상 이름은 대응을 위해 공개한다.
- 선택/대응 중 일반 행동과 패 열람·진화 비용 열람을 잠근다. 항복/승패 시 대기 상태를 정리한다. HTTP expectedVersion과 원자적 저장/실패 복구는 기존 경로를 사용한다.
- 하·중·상 AI는 같은 순수 준비 검사로 후보를 거르고, 슈는 자기 후보만 선택한다. 파괴 면역 제물을 골라 진행이 멈추는 경로를 막는다. 인간 선택/대응 중 AI는 기다린다.
- 상태는 JSON 데이터로 저장되므로 이후 사용자 개인 Cloudflare D1 저장소로 이전할 수 있는 형식을 유지한다. **D1 어댑터·연결·운영 배포는 아직 미완료**이며 [별도 계획](CLOUDFLARE_D1_PLAN.md)을 따른다.
